# v2.1.0 能力验证：两个真实案例

> 目的：不靠描述，用两个可打开的页面证明 SKILL 能产出什么，以及每条规则落在哪。
> 产物：`tests/test11-v2-industrial-site.html`（PC 网站）、`tests/test12-v2-inspection-h5.html`（H5）

---

## 案例一 · PC 网站（工业质检品牌页）

### 输入（按 A-1 需求卡）
- 画像：制造企业的设备/质量负责人，40 岁上下，桌面端，一年看 2-3 次供应商页面
- 核心任务：判断"这东西能不能装到我产线上"，然后预约试跑
- 场景：办公室，白天，同时开 10 个标签页，平均停留 40 秒
- 成功标准：30 秒内看懂"怎么测、准不准、怎么接"
- 明确不要：不要"赋能/闭环/生态"这类词，不要演示视频

### 旋钮与五轴（3.13）
```
SOUL 7 · SPECTACLE 6 · DENSITY 4
A 配色：暖纸底 + 单一深绿（工业安全色）+ 锈红仅作告警
B 字体：宋体做 display + 无衬线正文（刻意的字族对比，不是默认裸用）
C 版式：非对称 hero（1.35fr / 1fr）+ 4 列细线规格条
D 引擎：CSS-only（扫描线 + 标注浮现），不引 WebGL
E 材质：纸张颗粒 + 深色面板 + 半透明描边
```
与上一条构建（医疗工作台，蓝色 + 平铺卡片）在 **A/B/C/E 四个轴上不同**，满足"≥3 轴不同"。

### 页面证明了哪些规则

| 规则 | 落点 |
|---|---|
| 一屏一个焦点 | hero 只有一句主张；右侧检测卡是**证据**不是第二个焦点（字号小 3 档） |
| 昂贵感物理层 | 全站 `feTurbulence` 颗粒 `.035`；无纯白（纸底 `#F4F2ED` / 卡 `#FBFAF7`）；中性色带暖调 |
| 宣称即交付（SPECTACLE 6） | 扫描线是真跑的 CSS 动画，只走一次，可手动重播；没有假装 WebGL |
| 四骨架（落地页） | HERO → 规格条 → **论证（扫描演示）** → 工艺三步 → 超大 CTA |
| 反模式规避 | 无渐变背景、无玻璃拟态、无 eyebrow、无 `01/02/03` 装饰编号（三步是真序列才编号）、无假精确数字（99.2% 标注了 4.8 万件样本口径） |
| 移动端六条 | `overflow-x:clip`；hero 在 620px 断点折叠；导航在窄屏隐藏而非挤压 |
| 动效五类 | 入场（导航理解 420ms 编排，主内容先、证据卡 +120ms）、扫描（一次性的焦点引导，3.2s 但只播一次）、按钮按下（状态反馈 100ms） |
| 记忆点唯一 | 扫描线 + 两处缺陷标注浮现；其余全部静止（无 hover 弹跳、无循环光晕） |

### 六段设计依据（摘要）

1. **层级**：焦点是 h1 的"过一遍光"（78px 衬线 vs 正文 16px，4.8 倍）；靠尺寸 + 衬线/无衬线的字族对比建立，不靠颜色；去色后仍是"标题 → 说明 → 证据卡 → 数字条"。
2. **降成本**：核心任务是"判断能不能用"，所以第二屏直接给**检测记录**（时间、工件、缺陷、判定），而不是功能列表；CTA 出现两次（hero + 底部面板），都指向同一动作。
3. **不拥挤**：DENSITY 4 —— 每屏一个主张 + 一组证据，区块间距 `clamp(72,9vw,128)`；信息分级靠字号与留白，没有删任何规格数字。
4. **特效**：保留 3 个（入场编排、扫描、按下反馈），删除"滚动视差""数字滚动""卡片 hover 抬升"——它们说不出服务哪类功能。
5. **模块映射**：见下。
6. **记忆点**：扫描线沿工件走一遍，两处缺陷依次浮现并标注尺寸；只在首屏出现一次，其他区域全部安静。

| 模块 | 动效 | 触发 | 目的 | 时长 | 降级 |
|---|---|---|---|---|---|
| 首屏 | 位移 14px + 淡入（编排） | 进入视口 | 导航理解 | 420ms | 直接显示 |
| 扫描演示 | 扫描线 + 标注浮现 | 载入 / 重播 | 焦点引导 | 3.2s（一次） | 隐藏扫描线，标注常显 |
| 主按钮 | 缩放 .975 | 按下 | 状态反馈 | 100ms | 仅颜色 |
| 导航链接 | 下划线展开 | hover | 状态反馈 | 180ms | 无 |

### 审计结果
```
preflight: 0 error · 0 warning
contrast: 0 违规；最低 5.20:1（muted on paper）；深色面板文字 15.51:1
```

## 案例二 · H5（设备点检）

### 输入
- 画像：车间一线点检员，35-50 岁，戴手套、强光、单手持机
- 核心任务：知道"还剩几台、哪台异常"，然后开始点检
- 场景：车间，早班 8:00-12:00，强光直射屏幕，可能戴手套
- 成功标准：3 秒知道还剩多少、异常在哪台；单手能完成开始动作

### 旋钮
```
SOUL 6 · SPECTACLE 3 · DENSITY 6（B 端工具，密度偏高）
```

### 页面证明了哪些规则

| 规则 | 落点 |
|---|---|
| 渐变头 + 白面板上浮（P-002） | 头部 200px，白面板 `margin-top:-24px` + 圆角 20 |
| 图标宫格 5×2（M-002） | 10 项，48px 圆形软底，标签 11.5px，第 10 项"更多" |
| 触控 ≥44px | 每格 `min-height:68px`、行 `min-height:64px`、按钮 48px |
| 吸底 ↔ 安全区（说法层成对坑） | `.bar` 固定底部，`padding-bottom: calc(10px + env(safe-area-inset-bottom))` |
| 输入框 ≥16px | 搜索框 `font-size:16px`，避免 iOS 聚焦缩放 |
| 键盘 100dvh | `min-height:100dvh`，不用 `100vh` |
| 一屏一个焦点 | 焦点是"今日待点检 14"（28px），异常用锈红只做**状态**，不做装饰 |
| 呼吸 ≤2 | 仅"异常"徽章前的小圆点 2s 脉冲，全页唯一 |
| 动效时长 | 面板上浮 300ms（导航理解）、行展开 150ms（空间过渡）、按下 100ms（状态反馈） |
| 深浅双模式 | 跟随系统 + 手动切换，令牌成对定义，审计 26 组全过（最低 7.55:1） |

### 六段设计依据（摘要）

1. **层级**：焦点"14 台"；靠尺寸（28 vs 15，1.87 倍）+ 位置（白面板第一行）建立；去色后仍能读出"待点检 → 异常 → 宫格 → 列表"。
2. **降成本**：核心任务从"进列表 → 找设备 → 点开始"3 步缩到 1 步（吸底"开始点检"直接进最近未完成设备）；异常设备排第二行且默认展开，减少一次查找。
3. **不拥挤**：DENSITY 6，行高 64、卡内 14、区块 24；信息三级：28px 数字 / 15px 设备名 / 12px 元信息（仍然 4.5:1 以上）。
4. **特效**：保留 4 个（面板上浮、行展开、按下反馈、异常点脉冲），删除"宫格逐个弹入""底部按钮循环发光"。
5. **模块映射**：见下。
6. **记忆点**：**没有额外加记忆点**——这是工具页，工人每天用 4 次，任何"惊喜"都会变成第 5 次的噪音。唯一的"活"是异常点的脉冲，它服务的是"这里有东西要处理"。

| 模块 | 动效 | 触发 | 目的 | 时长 | 降级 |
|---|---|---|---|---|---|
| 面板 | 上浮 10px + 淡入 | 页面载入 | 导航理解 | 300ms | 直接显示 |
| 设备行 | 高度展开（grid-rows） | 点击整行 | 空间过渡 | 150ms | 直接展开 |
| 开始点检 | 缩放 .97 | 按下 | 状态反馈 | 100ms | 仅颜色 |
| 异常徽章 | 圆点脉冲 | 常驻 | 焦点引导 | 2s 循环 | 静态圆点 |

## 这两个案例说明"能做到什么"

| 能力 | 证据 |
|---|---|
| 品牌型 PC 网站（要有记忆点、要显贵） | test11：非对称 hero + 单一引擎 + 颗粒质感 + 论证段 |
| 工具型 H5（要好用、要耐看） | test12：渐变头 + 宫格 + 吸底安全区 + 单手可操作 |
| 不是"套模板" | 两页在五个轴上完全不同：暖纸/深绿 vs 绿渐变/白面板；衬线 vs 无衬线；非对称 vs 单列；CSS 扫描 vs 无引擎 |
| 可解释 | 两页都有完整的六段依据与动效映射表 |
| 可验收 | `preflight` 0/0；`contrast` 0 违规（11 个测试页全部通过） |

**做不到 / 不该期待**：
- 需要真实三维渲染的（WebGL 流体、雷达成像）——只能给结构 + 降级方案，不能凭 CSS 假装
- 需要真实数据接入的——蓝图能定义数据地板，但字段要你确认真实来源
- 需要品牌资产（真实产品照、logo、字体授权）的——缺素材时我会说明，而不是用装饰插画填位
