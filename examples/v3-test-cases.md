# v3.1 规则落地验证：三个场景

> 目的：证明改写后的 SKILL 在每个场景**会输出什么**，以及每条规则在哪里生效。
> 每例按 §11 的 8 段格式压缩呈现（Spec 与代码从略，保留决策层）。

---

## 案例 1 · 官网首页（PC Web）

**1 需求解析**
- 平台：PC Web，内容宽 1440（营销）
- 用户：数据平台负责人，30–45 岁，桌面，决策期停留 40–90 秒
- 核心目标：让访客在 30 秒内理解"接入要多久、能省多少"，并进入试用
- 关键页面：首页（单屏滚动 5 屏）

**2 定调**
```
参考 1：Stripe —— 借鉴「规格条用细线 + 真数字、表格即证据」的手法
参考 2：Linear —— 借鉴「1px 低对比描边 + 单一强调色 + 高信息密度」的手法
情绪词：冷静 → 暖纸底 #F7F6F3 / 无渐变 / 全站 1px 描边
        精密 → 8pt 网格 / 数字 tabular / 圆角 ≤12
        果断 → 强调色 #1A5CFF 仅用于 CTA 与关键数字，面积 <8%
```

**3 Design Spec 摘要**
| 项 | 值 |
|---|---|
| 主色/强调 | `#1A5CFF` / `#C2410C`（仅"延迟告警"一处） |
| 中性阶 | `#FAFAF8 → #0D0F12`，11 档，暖偏 2° |
| 字阶 | 13 / 16 / 20 / 25 / 31 / 39 / 49（1.25） |
| 字体 | 展示 Instrument Serif（≥31px）/ 正文 Geist Sans |
| 行高 | 标题 1.05，正文 1.65 |
| 间距 | 96 hero / 64 区块 / 24 卡内 / 32 卡间 |
| 圆角 | 8 按钮 / 12 卡片 / 20 弹层 |
| 阴影 | 3 档带色（`rgba(13,15,18,.06/.10/.16)`） |
| 网格 | 12 列 / 沟槽 32 / 边距 64 / 内容 1360 |
| 动效 | 120/180/240/320/420；`cubic-bezier(.22,1,.36,1)` |

**4 线框（首屏）**
| 序 | 区块 | 层级 | 说明 |
|---|---|---|---|
| 1 | 主张标题（衬线 49px，占 7 列） | 1 焦点 | 靠尺寸 + 字族对比 + 左对齐孤立 |
| 2 | 右侧"管道延迟"实时卡（5 列） | 2 | 承载证据，非第二焦点（字号小 3 档） |
| 3 | 规格条（4 列细线 + 真数字） | 3 | 24s 接入 / 12ms 延迟 / 99.98% 可用 |
| 4 | 架构示意（横向 3 段 + 箭头） | 3 | 用真实组件名，不用抽象图标 |
| 5 | CTA（一个主 + 一个文字链） | 2 | 主按钮唯一高强调 |

- 非对称点：**7:5**（标题 7 列 / 证据卡 5 列），第二屏改为 8:4 反向
- 密度：宽松（区块 64，卡内 24）

**5 组件选型**
| 组件 | 来源 | 为什么 | 替代 | 成本 |
|---|---|---|---|---|
| Button / Dialog | shadcn/ui | Radix 行为、源码可改 | 原生 + 自写 ARIA | 0 依赖 |
| 数字滚动 | 自写 rAF（35 行） | 只需一次计数，引库不值 | Motion | 0 |
| 图标 | Lucide | 线性统一、16/20/24 | Phosphor | 0 |
| 字体 | Instrument Serif + Geist | 衬线承担语气、无衬线保证可读 | 思源宋/黑 | 2 文件 |

**6 动效（表）**
| 模块 | 动效 | 触发 | 时长 | 缓动 | 降级 |
|---|---|---|---|---|---|
| 首屏 | 标题位移 16px + 淡入 | 载入 | 420ms | out-quint | 直接显示 |
| 规格条 | 数字 0→目标值 | 进入视口 once | 800ms | out-quint | 直接显示终值 |
| 卡片 | translateY(-3px) + 阴影升级 | hover | 180ms | out-quint | 无位移，仅边框 |
| CTA | scale(.97) | active | 120ms | out-quint | 仅颜色 |

**7 评分**：层次 9｜排版 9｜色彩 8｜动效 8｜交互 8｜平台 9｜独特 8 → **8.4**
**8 可继续优化**：① 规格条数字加单位缩排（单位 13px、基线对齐）；② 第二屏架构图改为可横向 scrub；③ 强调色 `#C2410C` 在深色段需提亮到 `#E8632E`。

## 案例 2 · 小程序列表页（工单）

**1 需求解析**
- 平台：微信小程序（750rpx）
- 用户：设备维保员，35–50 岁，车间强光，单手，戴手套
- 核心目标：30 秒内找到"我的待处理工单"并开始处理
- 关键页面：工单列表（单屏）

**2 定调**
```
参考 1：WeUI —— 借鉴「列表行左信息右动作、点击整行」的手法
参考 2：Linear —— 借鉴「状态用色点 + 文本，不用大色块」的手法
情绪词：明确 → 状态点 6px + 文案，不用彩色卡片
        耐看 → 中性阶 11 档，主色 #14603F 仅用于主按钮与状态
        高效 → 行高 112rpx，一屏 5 行，无需滚动即可决策
```

**3 Design Spec 关键约束（G 生效）**
- 单位 **rpx**：单边 24rpx = 12px；行高 112rpx = 56px
- **胶囊避让**：自定义导航预留 `statusBarHeight + 44px`，标题右边界距屏右 ≥96rpx
- **包体积**：无第三方组件库，自绘列表（避免 Vant Weapp 全量引入）
- **不支持特性替代**：`backdrop-filter` → 半透明纯色 `rgba(255,255,255,.92)`；`position:fixed` 内滚动 → 纵向布局 + 吸底
- 字号：正文 28rpx（14px），标题 32rpx（16px），元信息 24rpx（12px）

**4 线框**
| 序 | 区块 | 层级 | 说明 |
|---|---|---|---|
| 1 | 导航栏（标题 + 筛选入口） | 2 | 预留胶囊右侧 96rpx |
| 2 | 状态筛选 chips（全部/待处理/已完成） | 3 | 选中态：底色主色 12% + 深字 |
| 3 | 工单行 ×5 | 1 焦点 | 左：设备名（32rpx/600）+ 位置时间（24rpx）；右：状态点 + 文案 |
| 4 | 吸底主按钮"开始处理" | 2 | 距底 `env(safe-area-inset-bottom) + 16rpx` |
| 5 | 空态（无工单） | — | 一句说明 + "查看已完成" |

- 非对称：**8:4**（左侧信息 8 份 / 右侧状态 4 份），避免整行等分
- 密度：紧凑（行 112rpx、区块 48rpx）

**5 组件选型**
| 组件 | 来源 | 为什么 | 替代 | 成本 |
|---|---|---|---|---|
| 列表/按钮 | 自绘（原生 view/button） | 包体积优先，无主题定制需求 | Vant Weapp | 0 |
| 图标 | Lucide SVG 转 base64 | 单库统一，2 个图标 | TDesign 图标 | +8KB |
| 动效 | 纯 CSS | 小程序重动画易掉帧 | 无 | 0 |

**6 动效（≤300ms，G 约束）**
| 模块 | 动效 | 触发 | 时长 | 降级 |
|---|---|---|---|---|
| 列表行 | 背景 `#F4F6F5` | 点按 | 0（即时） | 无 |
| 工单行展开 | grid-rows 0→1fr | 点击 | 240ms | 直接展开 |
| 吸底按钮 | scale(.97) | 点按 | 120ms | 仅颜色 |
| 状态点 | 2s 脉冲（仅"待处理"1 处） | 常驻 | 循环 | 静态点 |

**7 评分**：层次 8｜排版 8｜色彩 8｜动效 8｜交互 8｜平台 9｜独特 7 → **8.1**
**8 可继续优化**：① 状态点改 8rpx 提升强光可见性；② 筛选 chips 增加数量徽标；③ 空态补一张设备线稿（≤12KB）。

## 案例 3 · APP 详情页（iPhone 优先）

**1 需求解析**
- 平台：iOS APP（Cupertino，**不与 M3 混用**）
- 用户：科室主任，45–60 岁，iPad/iPhone 混合，门诊间隙查看
- 核心目标：3 分钟内确认参数并提交采购意向
- 关键页面：设备详情（单屏滚动 + 吸底操作）

**2 定调**
```
参考 1：Apple HIG（Cupertino）—— 借鉴「大标题折叠为导航标题、分隔线内缩」的手法
参考 2：Stripe —— 借鉴「价格与明细右对齐等宽、CTA 常驻」的手法
情绪词：可信 → 中性偏冷 #F7F8FA、留白充足、无装饰插画
        清晰 → 参数用定义列表（左标签/右值），不用卡片堆叠
        克制 → 主色 #0B5FFF 仅 CTA 与关键参数，面积 <6%
```

**3 Design Spec（iOS 关键项）**
- 单位 **pt**；触控 ≥44pt；正文 17pt（Dynamic Type 基准），标题 28pt
- **Cupertino**：大标题 → 滚动后折叠为导航栏标题（52pt 高）；返回手势保留，不自绘
- 底部安全区：吸底条 `padding-bottom: constant(safe-area-inset-bottom)` + `env(...)`
- 深色模式必须：`#0B0D11` 底 / `#EDEDF0` 字
- 圆角：10 / 14 / 20（iOS 视觉偏小）
- 阴影：仅 2 档，深色下用 1px `rgba(255,255,255,.10)` 描边

**4 线框**
| 序 | 区块 | 层级 | 说明 |
|---|---|---|---|
| 1 | 设备主图（4:3，`object-fit:cover`） | 1 焦点 | 首屏唯一大图，带 40% 渐变遮罩压标题 |
| 2 | 标题 + 型号 + 认证徽章 | 2 | 28pt / 600；徽章软底 12% |
| 3 | 关键参数（4 行定义列表） | 3 | 左标签 15pt 灰 / 右值 17pt 等宽 |
| 4 | 详细规格（折叠，默认收起） | 4 | 展开 240ms |
| 5 | 同类对比（横向滚动 3 卡） | 4 | 卡片 240pt 宽，间距 12pt |
| 6 | 吸底：价格 + "提交意向" | 2 | 价格 20pt 等宽 + 主按钮 48pt |

- 非对称：**8:4**（图 8 / 侧栏信息 4，iPad 横屏时启用）；iPhone 竖屏为**出血**（主图超出内容区 16pt）
- 密度：标准（行 48pt / 区块 32pt）

**5 组件选型**
| 组件 | 来源 | 为什么 | 替代 | 成本 |
|---|---|---|---|---|
| 导航/滚动折叠 | 自写（`scroll` + `transform`） | 需精确控制折叠阈值 | React Navigation Header | 中 |
| 底部操作条 | 自写 + safe-area | 需常驻且不遮挡内容 | Paper BottomBar | 0 |
| 折叠面板 | 原生 + `grid-rows` | 无依赖、可访问 | RN Accordion | 0 |
| 图标 | SF Symbols（iOS 原生） | 平台一致 | Lucide | 0 |

**6 动效**
| 模块 | 动效 | 触发 | 时长 | 缓动 | 降级 |
|---|---|---|---|---|---|
| 大标题折叠 | 字号 28→17pt + 位移 -8pt | 滚动 >64pt | 跟手（无固定时长） | linear（跟手映射，允许） | 直接切换 |
| 规格展开 | grid-rows 0→1fr | 点击 | 240ms | out-quint | 直接展开 |
| 提交按钮 | scale(.97) + 成功勾线 220ms | 点按/成功 | 120/220ms | out-quint | 静态勾 |
| 同类卡片 | 横向惯性滚动 | 手势 | 系统惯性 | 系统 | 无 |

**7 评分**：层次 9｜排版 8｜色彩 8｜动效 8｜交互 9｜平台 9｜独特 8 → **8.4**
**8 可继续优化**：① 参数值加 `tabular-nums` 并统一单位位置；② 折叠阈值改为 64pt 并加 8pt 吸附；③ 深色下主图遮罩加深到 55%。

## 三例共同证明的四件事

1. **平台先行**：三例的 Spec 从单位（px/rpx/pt）与约束（胶囊避让/安全区）开始，而不是从配色开始
2. **数值可查**：每条动效都有时长+缓动+降级；每个间距都能在 4/8 体系里找到
3. **规则能触发**：`7:5 / 8:4` 非对称、8 态、≤300ms（小程序）、44pt（APP）、20 条 F 清单，均可逐条核对
4. **评分可执行**：三例总分 8.1–8.4，且都低于 9 的维度写了具体改进参数——说明评分不是走过场
