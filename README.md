> 大多数"UI 美化"技能能生成好看的界面，但不会诊断、不会解释、也不会克制。
> 这一版换了目标：**先看懂问题，再动手；每个决定都能说出为什么；能用小改解决的绝不重做。**

---

## 它凭什么不一样

| 普通 UI 技能 | 这一版 |
|---|---|
| 拿到页面就重画 | 先做**灰度测试**：去掉颜色后结构不成立，才允许动结构 |
| 说不出为什么 | 每个决策追溯到**一条原理**或**一项用户成本**（认知/操作/时间/错误/信任） |
| 平均用力 | 用 `影响人数 × 成本等级 ÷ 修复成本` **排序**，只修最值钱的三个 |
| 交付一张图 | 交付**诊断报告 + 方案 + 预览 + 六段设计依据 + 自检结果** |
| 越改越花 | 12 条反模式红线 + 一屏一个焦点 + 一处记忆点 |

## 三分钟上手

### 1. 安装

```bash
npx skills add https://github.com/pz857082775/website-ui-designer --skill website-ui-designer
# 或把目录拷到你的 Agent 技能目录（WorkBuddy: ~/.workbuddy/skills/）
```

### 2. 说一句话

| 你想做的事 | 可以直接这么说 |
|---|---|
| 觉得界面丑但说不上哪不对 | "帮我诊断这个页面，别重做，告诉我最该改的三处" |
| 要美化但怕失去可用性 | "美化这个后台首页，但不要动信息结构" |
| 要一个设计系统 | "给我一套 token：三层语义、浅深两版、含多端换算" |
| 要评审 | "按设计总监的标准评审这版稿子，指出问题并给替代方案" |
| 要动效方案 | "给这个页面做动效决策表：模块/触发/目的/时长/降级" |
| 整改 AI 味 | "这个页面 AI 味很重，逐条指出命中了哪些反模式" |

### 3. 你会拿到什么

```
① 诊断报告   必修 / 应修 / 可延 三段清单 + 明确"不改什么" + 优先级算式
② 设计方案   token 变更 → 组件契约 → 结构（仅必要时），浅/深两套
③ 预览       3 个关键屏的可点 HTML（首屏 / 主流程 / 状态屏）
④ 设计依据   六段，逐条填满（本技能的核心交付）
⑤ 动效映射表 功能模块 / 动效 / 触发 / 目的 / 时长 / 降级
⑥ 自检结果   七问逐条回答 + 自动审计输出
```

## 六段"设计依据"长什么样

> 完整示范见 [`examples/design-rationale-demo.md`](./examples/design-rationale-demo.md)（工厂点检 App 首页改造）。

**① 层级依据**：焦点是"待点检 14"，靠尺寸 28px（次级的 1.65 倍）→ 对比（唯一深黑数字）→ 孤立（四周留白 24px，是全屏平均的 1.6 倍）建立。去色缩到 25% 后，阅读顺序仍是 `待点检 → 异常 → 宫格 → 列表`，灰度测试通过。

**② 降低成本**：核心任务"开始点检"从 4 步缩到 2 步——把高频入口从宫格提升为首屏主按钮，并预填上次设备。可点击性靠"唯一实心色 + 44px 高 + 按下 scale(.97)"暗示；报表/历史折进"更多"。

**③ 不拥挤**：舒适模式，因为一线人员在车间强光下单手持机、日均 1-2 小时（不满足紧凑模式的三条理由）。行高 48、卡内 20、区块 32，空域 38%，来自间距而非缩小字号。三级降权：28/700 → 17/500 → 13/400（仍 4.6:1）。**没有删信息**，只做了折叠。

**④ 特效取舍**：保留 4 个（按下反馈 100ms、展开 150ms、筛选淡入 160ms、聚焦 280ms），删除 3 个（banner 循环光斑、全屏 fade-up、宫格 hover 弹跳）——后三者说不出服务哪类功能，且抢主任务焦点。

**⑤ 模块映射**：（表格，含 5 行动效与降级方案）

**⑥ 记忆点**：最后一台设备完成时，顶部任务条从 `3/12` 推进到 `12/12`（220ms 刻度依次点亮）+ 底色转成功色，停留 1 秒。一天只出现一次；列表滚动、筛选、宫格点击时全部保持静止。

## 2.1 新增的三层能力（来自 finesse 系列）

| 能力 | 解决什么 | 关键规则 |
|---|---|---|
| **品牌方向**（`brand-direction.md`） | 同一方法产出互不相关的页面，而不是十张同一张脸 | 三旋钮 `SOUL/SPECTACLE/DENSITY`；五正交轴组合（配色/字体/版式/引擎/材质）；新方案与上一条 **≥3 轴不同**；`SPECTACLE ≥7` 必须真的有引擎 |
| **工作台蓝图**（`workbench-blueprint.md`） | 工作台做成"功能菜单 + 漂亮但没用的数字" | 五部件顺序不可换：**身份 → 钩子 → 数据地板 → 模块 → 收入缝**；五个问题（字段/写入/时机/第一天/断源）；**幸运饼干测试** |
| **说法层**（`terminology-layer.md`） | 用户只说症状（"按钮被黑杠挡住"），说不出成因（安全区） | 三条门禁：指得出触发词 / 成对的坑一起给 / 结果在前术语在后；一次最多 1-3 条 |

**"昂贵感"的物理层**（品牌页可用，后台不用）：颗粒噪点 `opacity .025-.05`、半透明描边、不用纯白纯黑（中性色朝品牌色相偏 2-6 点）、色彩锁定、字体张力（负字距 + 行高 .86-.95，**全大写行高下限 1.0**）。

**移动端六条硬规则**：`overflow-x: clip` 不用 hidden / 含图轨道 `minmax(0,1fr)` / 可点文字不换行 / 标题 `overflow-wrap:anywhere` / 只一个 `top:0` sticky / 全大写标题行高 ≥1.0。

## 2.2 新增：组件库 / 字体 / 品牌规范

| 能力 | 解决什么 | 关键规则 |
|---|---|---|
| **组件库接入**（`component-library.md`） | 有零件，但装出来还是一眼模板 | shadcn 源码归你 → 升级要 diff；**必须重做圆角/边框/阴影/字阶四件事**；只允许用 variant 控制，禁止 `!important`；Radix 的无障碍不要重造 |
| **字体系统**（`typography-system.md`） | 换个字体就"高级"，但常踩中文与授权坑 | 字族 ≤2、字重 ≤3、woff2 ≤4 个 ≤300KB；中英分别声明；中文层级靠字号不靠 300 字重；数字等宽 |
| **品牌规范库**（`brand-spec-library.md`） | 从零猜配色，或直接抄成山寨 | 只提取四件事（色阶/字阶/组件契约/栅格）+ 品牌禁忌；映射到 12 令牌后**必须跑对比度**；不复制 logo/字体 |

主题落地文件：`templates/shadcn-theme.css`（`--background/--foreground/--primary/--ring` 四个关键映射 + 圆角/间距/字阶）。

**一个关键判断**：shadcn 的默认皮肤本身就是新的"AI 脸"——它让你快速得到"合格的默认"，
不重做四件事，你的页面会和几十万个 shadcn 项目长得一样。

## 2.7 三个中间层（v3.4）

| 层 | 解决什么 | 入口 |
|---|---|---|
| **术语**（110 条 / 11 类） | 用户只说症状（"黑杠挡住按钮"），说不出成因（安全区） | `library/ui-glossary.md` + `python scripts/term_lookup.py "<原话>"` |
| **模板**（21 类） | 用户没灵感，不知道这种页面该长什么样 | `library/ui-templates.md`（骨架 + 参数 + 状态 + 记忆点 + 翻车） |
| **规范**（五件套） | 只有描述，写不出代码 | `library/design-spec-kit.md`（令牌 + 六区块代码 + 状态矩阵 + 响应式表） |

**串成一条线**：`原话 → term_lookup（术语）→ ui-templates（结构）→ design-spec-kit（令牌+骨架）→ audit_all（验收）`

实测反查：
```
"按钮被底下那条黑杠挡住了" → 安全区（env(safe-area-inset-bottom)）
"页面太土了"               → 中性阶 / 饱和度
"太挤了"                   → 间距系统
```

## 2.6 真实渲染审查（v3.3）

用 Edge 无头截图 + iframe 390 实测三页，发现并修掉 6 类**只有渲染后才看得见**的缺陷：

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 首屏预隐藏 | 整块内容半透明（`.rise{opacity:0}` 等 JS 加类） | 入场改 CSS `@keyframes ... both`，默认可见 |
| 截图假象 | Windows Chrome 最小窗口宽 478，`--window-size=390` 会渲染 478 再裁 390 | 用 iframe 390 / 设备模拟，只认 `scrollWidth === clientWidth` |
| CJK 大字裁顶 | 「陈月华」字形上沿被切 | 行高 ≥1.3 + 4px 上内边距；折叠改 `grid-rows`，不用 `max-height` |
| 头像 `1fr` 撑大 | 头像高过文字块一倍 | 固定 72px，信息块 `minmax(0,1fr)`，`align-items:start` |
| 链接污染标题 | 整卡 `<a>` 让标题变蓝带下划线 | `color:inherit;text-decoration:none` |
| 图表中间态 | 风险环停在「3」 | HTML 写终值，CSS 动画只做增强；轨道要有可见色 |

**新增验收方法（§5.7）**：结构（去色 25%）→ 溢出（scrollWidth 实测）→ 文字（计算样式跑 runtime）。
截图只能证明"这一帧长这样"，不能作为验收结论。

## 2.5 三类真实事故（v3.2 修正）

| 事故 | 根因 | 新规则 |
|---|---|---|
| 按钮"看得见底、看不见字" | `.nav a` 的 `color`（特异性 0,1,1）覆盖了 `.btn-primary` 的白字（0,1,0） | **三色一体**：背景与文字必须在同一条规则里声明；覆盖时选择器必须含 `.btn` |
| 滚动时筛选条被搜索框压住 | 搜索与 chips 各自 sticky，两层相互覆盖 | **单固定层**：同容器只允许一个 `top:0` sticky；多层用 `--nav-h` 依次偏移、z-index 递减 |
| 布局不错但"配色丑" | 冷灰底 + 标准蓝（白字仅 3.16:1）+ 正红 + 三色标签 | **配色配方**：深主色 L\* 28–38%、语义色降饱和 8–12%、同屏有彩色系 ≤2；5 套色板可直接用 |

**为什么 token 审计没抓到第 1 类**：`audit_contrast.py` 只比对令牌配对，看不到 CSS 特异性。
新增运行时检查：浏览器控制台粘贴 `scripts/contrast_runtime.js`，读真实计算样式，**输出 0 违规才算过**。

## 2.4 组件能力库：先认语义，再挑原语

| 来源 | 能力域 | 抓取实测 |
|---|---|---|
| **shadcn/ui** | 基座（可访问行为 + 可组合样式） | 50+ 组件 |
| **Beautiful UI** | AI 原生原语（Loading/Thinking/Streaming/Approval/Tool Chips/Task Rows/Chat/Prompt Bar…） | **21 个**，每个带状态机 |
| **beUI** | 精致交互（Dock/命令面板/形变弹层/数字动画） | **71 个**，Motion 驱动，走 shadcn registry |
| **Rare UI** | 去模板化视觉（Fluid Orb/Gravity Letters/Folder） | **27 个**单文件组件 |
| **Transitions** | 过渡与微交互（shared axis / origin-aware / card resize / number pop-in） | **43+** |

**检索顺序**：`shadcn 基座 → beUI/Rare 定风格 → Transitions 加质感 → Beautiful UI 补 AI 原语`。
顺序不可颠倒：基座决定可访问性与工程成本，AI 原语只在有 AI 过程时才启用。

**语义映射（节选）**：AI 加载→Loading State｜AI 推理→Thinking trace｜流式→Streaming Text｜
执行前确认→Approval Card｜工具调用→Tool Chips｜长任务→Task Rows｜批量编辑→Diff Table｜
CRM→Records Table｜筛选→Filter Table｜知识来源→Context Cards｜洞察→Insight Cards。

**落地铁律**：抽象语义，不照搬视觉。用项目自己的主色/圆角/字体重绘，但保留状态机、时序与可访问性。
**五道闸门**：原语选对 / 基座可访问 / 动效有时长与降级 / 无模板味 / 标注来源与降级方案。

完整版含 33 条映射与四个站点的抓取清单：[`references/component-capability-library.md`](./references/component-capability-library.md)。

## 2.3 治理：29 份文件谁负责什么

**七层，每层只有一个负责人；跨层冲突时下层服从上层。**

```
L0 宪法    SKILL.md + skill-architecture.md
L1 输入    design-intake · terminology-layer · rag
L2 方向    brand-direction · brand-spec-library
L3 结构    workbench-blueprint（+ dashboard-style 行业细节）
L4 系统    token-architecture · typography-system · component-library
L5 表现    motion-decision-table（决策）· motion-spec（参数）· visual-interaction-spec（可读性）
L6 交付    review-rubric · audit_all.py · examples
```

**已冻结（保留但不再作为依据）**：`anti-slop`（并入 anti-patterns）、`style-library`（选模板=同质化）、
`redesign-mode`（并入 diagnosis-protocol）、`prompt-anatomy`（被五轴+六段契约取代）。
`gsap-prompts` / `design-system-spec` / `dashboard-style` 降为"实现层参考"；`prompt-master` 只作输出格式。

**调用顺序（P0-P6）**
```
P0 灰度测试 + 对比度/触控/焦点  →  不过就停，先修结构
P1 三问 + 术语翻译 + 检索
P2 旋钮 + 五轴（≥3 轴不同）+ 品牌规范
P3 骨架 / 工作台五部件 + 数据地板
P4 令牌 → 字体 → 组件
P5 动效决策 → 参数 → 8 态与成功动画
P6 六段依据 → 评分 → 一条命令过闸 → 七问自检
```
唯一不可跳过的是 **六段设计依据**；其余按条件可省（详见 `skill-architecture.md` §4.2）。

**一条命令过闸**
```bash
python scripts/audit_all.py tests/*.html
# 1. preflight（7 类硬伤）  2. contrast（浅/深全配对）→ PASS / FAIL + 前三条必修
```

**趋势立场**：趋势只提供默认值，不提供正确性。当下的共识是低饱和静奢、编辑式栅格、质感物理层、
克制动效、语义令牌、AI 原生界面、表格回归、无障碍默认；满屏玻璃拟态、紫蓝发光、每段 pill、
假大数字、装饰 3D、组件库默认皮肤属于高危项。

## 内建的 UI 认知（12 条）

| # | 认知 | 可执行的规则 |
|---|---|---|
| 1 | 层级与焦点 | 尺寸 > 对比 > 位置 > 颜色；一屏一个焦点 |
| 2 | 格式塔分组 | **内部间距 ≤ 外部间距**，违反即分组崩塌 |
| 3 | 间距系统 | 4/8 步进，语义命名；留白从"过多"删到"刚够" |
| 4 | 排版 | 5 档角色；正文 ≥16（移动 mockup ≥14）；行高 1.5-1.6；字重只用 400/500/700 |
| 5 | 色彩 | 原始→语义→组件三层；主色 ≤2 家族；中性 4-6 档；oklch 生成 |
| 6 | 对齐 | 1-2px 错位即"粗糙"，零容忍 |
| 7 | 密度 | 舒适（默认）/ 紧凑，选紧凑必须给三条理由 |
| 8 | 可访问性 | 触控 ≥44px、焦点环可见、键盘可达、reduced-motion 降级 |
| 9 | 多端 | 决策只在 token 层做，转换层换单位，渲染层只消费 token |
| 10 | 动效 | 五类：反馈 100 / 过渡 150 / 导航 200 / 引导 ≤300 / 等待安抚；不用 linear |
| 11 | 记忆点 | 只 1 个、只出现 1 次、可跳过、不阻断 |
| 12 | 用户成本 | 认知/操作/时间/错误/信任，用算式排序 |

## 12 条反模式红线

默认禁止：通用渐变背景 · 圆角+左侧色块卡片 · 卡片套卡片 · 每段都变 pill · 发光暗色模式 · 默认字体裸用 · 无意义 hero 大数字 · 装饰性 SVG 插画 · 无功能动效 · 与主任务抢焦点的特效 · 降对比度来"弱化" · 全站同一圆角阴影。

新增 6 条：正文长破折号 · 渐变文字 · 每节都挂 eyebrow · 完全相同的卡片栅格 · 假精确数字 · 该有图的位置没图。

命中 **≥3 条** = 不是微调，而是换骨架 + 换签名手法。详见 [`references/anti-patterns.md`](./references/anti-patterns.md)。

## 冲突怎么裁（不和稀泥）

| 冲突 | 判断标准 |
|---|---|
| 信息丰富 vs 拥挤 | 单屏信息组 ≤5、每组 ≤7 项、空域 ≥35%。超线先折叠、再降权、再分屏，三条都做完才允许删 |
| 美观 vs 可用 | 可用性一票否决（对比度/触控/焦点任一不达标，方案不上线） |
| 一致 vs 记忆点 | 记忆点只 1 个，且不得改变交互语义 |
| 品牌色 vs 可读 | 品牌色做文本必须过 4.5:1，否则加深一档 |
| 紧凑 vs 可访问 | 触控 ≥40px、字号 ≥14px；做不到就放弃紧凑，改分页 |
| 动效 vs 性能 | 掉到 60fps 以下 → 砍动效，不砍结构 |

```
1 去掉颜色，它是否仍层级清晰、知道下一步做什么？
2 每个特效能否说出服务哪类功能？说不出就删
3 每个决策能否追溯到原理或用户成本？追溯不到就是拍脑袋
4 记忆点是否唯一、可跳过、不阻断？
5 内部间距 ≤ 外部间距？对齐误差 ≤1px？
6 对比度 ≥4.5:1、触控 ≥44px、焦点可见、reduced-motion 已降级？
7 六段设计依据是否齐全、且没有"高级感"这类空话？
```

## 常见问题

**和 v1.x 有什么本质区别？**
v1 是"提示词工程师"：把需求翻译成好提示词。v2 是"设计总监"：先诊断、再决策、必须解释、能用小改就不重做。工具链（审计脚本、知识库）全部保留并接入新流程。

**我不懂设计，能判断它的输出对不对吗？**
能。六段设计依据里每条都带具体数字与理由；你只需检查三件事：焦点是不是你说的那个、改动清单里有没有"不改什么"、记忆点是不是只有一个。

**它会不会又变成套模板？**
有三道约束：灰度测试不通过才允许改结构、能调 token 就不改组件、12 条反模式红线 + 一处记忆点上限。

**支持哪些端？**
电脑端、H5、小程序、APP。多端差异只出现在 token 转换层（px/rpx/pt-dp + 安全区），不允许各端各写一套色值。
