# 反模式红线（Anti-Patterns）

> 这些不是"风格偏好"，是**可判定的错误**：每一种都能说清它损害了什么。
> 默认禁止；用户明确要求时，必须写出"它服务于什么"并承担说明责任。

---

## 一、12 条红线（逐条给判定与替代）

### 1. 通用渐变背景
**判定**：页面底或大区块使用紫蓝/彩虹渐变，且渐变与内容含义无关（换一个产品也能用）。
**损害**：降低文字对比度、让所有内容看起来"同一层"、与竞品无法区分。
**替代**：纯色底 + 一处品牌色；或用 ≤4% 明度差的极轻色彩场（看似白，实则有温度）。
**例外**：品牌本身以渐变为资产（如支付/潮流品牌），且渐变有固定色标与规范。

### 2. 圆角 + 左侧色块卡片
**判定**：卡片左侧有一条 4px 竖色条，用来"表示分类"。
**损害**：颜色成了唯一分类线索（色盲不可用）；且这是 2020 年前后台模板的指纹。
**替代**：用标题字重、图标或分组标题表达分类；颜色只留给状态。

### 3. 卡片套卡片
**判定**：卡片内部再包一层同色圆角容器，边界重叠。
**损害**：边界层级混乱（哪个是组？）、增加无意义的视觉噪音。
**替代**：留白 + 分组标题；必须分区时，用不同底色（surface vs surface-raised）而非边框。

### 4. 每段都变 pill 标签
**判定**：一屏 pill/胶囊标签 >6 个，且用于分类而非状态。
**损害**：视觉噪音、挤压行高、让"状态"失去特殊性。
**替代**：只给"状态"用 pill（≤5 个）；分类用文本 + 分隔符或小标题。

### 5. 发光暗色模式
**判定**：深色底 + 高饱和外发光（`box-shadow` 彩色大 blur）作为主要层级手段。
**损害**：眩光、对比失控、长时间使用疲劳；发光区域文字常不达标。
**替代**：靠表面明度差（+6~8% L）与 1px 亮边框建层级；发光最多 1 处，且不做信息载体。

### 6. 默认字体裸用
**判定**：只用 Inter / Roboto / system-ui，且没有字距、字重、字号的策略。
**损害**：无性格、与其他产品同质；中文环境下还常出现行高与字距不适配。
**替代**：选一组有性格的字族（中文可配一款衬线做 display），定义 5 档角色与字距。

### 7. 无意义全屏 hero 大数字
**判定**：首屏有一个巨大数字（如 "10,000+"），但它不参与用户的任何决策。
**损害**：占用首屏最贵的位置，却没提供可行动信息；是"假装有数据"的典型。
**替代**：一句主张 + 一个与该主张直接相关的证据（真实截图/前后对比/具体客户）。

### 8. 装饰性 SVG 插画
**判定**：插画删掉后，用户对功能的理解没有任何损失。
**损害**：占位、拖慢首屏、让界面看起来像模板。
**替代**：删；或换成真实产品截图、真实数据可视化。

### 9. 无功能的动效
**判定**：说不出它属于五类（反馈/过渡/导航/引导/等待）中的哪一类。
**损害**：分散注意力、增加等待感、性能开销。
**替代**：删；如果确实需要"活"，用一处记忆点替代十处装饰。

### 10. 与主任务抢焦点的特效
**判定**：一屏出现两个同等强度的视觉焦点（如大 banner + 大 KPI 同时强调）。
**损害**：用户不知道先看哪，任务路径变长。
**替代**：保留一个，另一个降权（缩尺寸、降饱和、移到次屏）。

### 11. 降文字对比度来"弱化"
**判定**：次要文字对比度 <4.5:1，理由是"想弱化"。
**损害**：可达性违规；在强光/低亮度设备上不可读。
**替代**：用字号（-2~4px）、字重（400 vs 500）、留白来降权；颜色最多降一档且仍达标。

### 12. 全站同一圆角 / 同一阴影
**判定**：输入框、卡片、弹层用同一个圆角与同一层阴影。
**损害**：层级扁平；是"SaaS 卡片套装"的识别特征。
**替代**：圆角分级 8/14/20，阴影两级（近距 + 远距），按容器层级使用。

## 二、"AI 味"组合识别（命中 ≥3 条基本可判定）

```
□ 紫蓝渐变背景
□ 居中三件套：小标签 + 大标题 + 副标题
□ 一行 3-4 个图标卡片，图标在彩色圆角方块里
□ 每段都有 pill 标签
□ 卡片套卡片
□ 深色 + 霓虹发光
□ 全屏 hero 大数字
□ 装饰性 3D 插画
□ 所有区块都在 fade-up 入场
□ 全站一个圆角、一层阴影
□ 文字用 #999 表示"次要"
□ 按钮末尾统一加 "→"
```

**处理**：命中 ≥3 条 → 不是"微调"，而是**换骨架 + 换签名手法**，否则改完还是同一张脸。

## 三、反模式 → 替代手法对照速查

| 想表达 | 别用 | 用 |
|---|---|---|
| 科技感 | 霓虹发光 + 玻璃 | 深色 + 细发丝线 + 一个精确的强调点 |
| 高级感 | 全黑背景 | 低饱和 + 大留白 + 精确排版 + 一处暖色 |
| 有活力 | 彩虹渐变 | 一个高饱和强调色 + 大圆角 + 快反馈 |
| 数据丰富 | 满屏图表 | 主指标 1 个 + 趋势 1 个 + 明细折叠 |
| 年轻 | 到处插画 | 一组有性格的字体 + 一个 IP 符号 + 轻动效 |
| 专业 | 全灰 | 中性为主 + 严谨网格 + 一个强主色 |
| 简洁 | 删内容 | 删装饰，补字号、色彩场、真实图 |

## 四、例外流程（用户坚持时）

1. 要求用户说明**它服务于什么**（哪条原理、哪类用户成本）
2. 若成立 → 记录进交付说明："按用户要求保留 X，理由 Y，风险 Z"
3. 若不成立 → 明说风险，给出替代方案，由用户决定
4. 无论哪种，**不得在未说明的情况下静默使用红线手法**
