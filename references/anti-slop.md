# 反 slop 清单（Anti-Slop Rules）

> **状态（v2.3.0）：已冻结。** 与 `anti-patterns.md` 重复且条目更旧，仅作历史参考。现行为：**anti-patterns（20 条红线）**。

来源：taste-skill v2 对 247 个精选站点（One Page Love、Awwwards SOTD）的研究结论。
**AI 生成页面的默认病**：所有页面趋同于"平均值"——没有错，但没有任何决定。

## 一、默认病黑名单（出现即删）

| 症状 | 表现 | 替换成什么 |
|---|---|---|
| 居中三件套 | 小标签 + 居中大标题 + 副标题，下面一行图标卡片 | 左对齐编辑式排版、不对称构图、整片色彩、真实大图 |
| 图标卡片阵 | 3-4 个圆角卡片，每个一个彩色图标 + 标题 + 一句话 | 编号列表、时间线、真实产品截图、数据表 |
| 柔和渐变 | 紫蓝渐变横幅/按钮/背景 | 实色、品牌真实色、整片色彩场 |
| 细分隔线 | 区块之间 1px 灰线 + 等宽字体小 caption | 用留白、字号对比、色彩切换分隔 |
| 玻璃拟态滥用 | 满屏 backdrop-blur 卡片 | 只用于导航/浮层控件，其余实色 |
| 虚荣数字 | "10x faster"、"99.9%" 无出处的数字 | 真实可验证的数字，或删掉 |

## 二、只删不补 = 单薄（最重要的警告）

把标签、分隔线、卡片删掉后页面会变空、变薄——盲测里评审者反而更喜欢"有 tell 的丰富页面"而不是"空页面"。
删装饰的同时必须补实质：
1. **字号更大**：标题敢用 88-140px，正文 17-19px
2. **整片色彩**：区块级背景色切换（不是渐变，是实色场）
3. **真实图片**：这个主题世界里的照片/产品图/可运行界面（灰色占位块和 lorem 数字是最弱的图）
4. **内容完整**：每个区块承载完整信息，不写"Lorem ipsum"

## 三、创意的来源：客户的独有素材

赢的页面创意都来自"只属于这个客户的东西"（客户名字的含义、所在的街道、那个让它成为它的约束）；
输的页面有好的构图 + 类别级通用概念（"科技感""未来感"）。
**自检：把页面的标题换成竞品名字，如果依然成立，这个创意就是通用的，重做。**

## 四、画面框架检查（每轮必查）

- 首屏标题清晰可读
- 全页等宽边距，没有区块歪向一侧
- 没有来源不明的空白带
- 首屏 3 秒能说出这是什么页面

## 五、应用屏（仪表盘/后台）的相反纪律

安静面板、数字右对齐、色彩花在数据上；禁止渐变发光、图标放彩色方块、彩虹图表、虚构数字。

## 六、5 类 AI 视觉集群（来自 Anthropic frontend-design 校准）

这些组合本身不"错"，但它们是模型不问 brief 就会给的默认值。brief 没指定时必须避开：

| # | 集群 | 特征指纹 |
|---|---|---|
| ① | 暖奶油 + 陶土 | 背景 ≈`#F4F1EA`，高对比衬线标题，强调色 ≈`#D97757` |
| ② | 近黑 + 荧光 | `#0A0A0A` 底 + 单一酸绿/朱红 |
| ③ | 报纸风 | 发丝线、零圆角、密集多栏、小字号 |
| ④ | SaaS 卡片套装 | 内容切成完全相同的圆角卡、全站同一圆角、同一层 `rgba(0,0,0,.1)` 阴影、渐变当装饰 |
| ⑤ | 模板外壳 | 每个标题上方 ALL-CAPS eyebrow、`A · B · C` 元信息、`词 — 片段` 标签、`#0B0B0B` 假黑、小数据用等宽字体、按钮末尾加 `→` |

## 七、8 条排版 tell（出现即改）

1. 标题里只把一个词改成斜体/加粗/换色
2. 每个标题上方都挂全大写宽字距小标签
3. 内容上方加不必要的类型标签（"我们的优势："这类）
4. 非序列内容用 01/02/03 编号（只有步骤、时间线、排行才配编号）
5. 元信息用 `·` 拼成一串，代替真实的信息分组
6. 用 `#0B0B0B`、`#111` 冒充"黑"，导致配色发闷
7. 小数据标签用等宽字体（`MONO`）当装饰
8. 所有按钮/链接末尾统一加 `→`

## 八、结构即信息（Anthropic）

边框、编号、分隔线、eyebrow、图标——每一个都必须**编码信息**，不做装饰。
加任何结构元素前问一句："它传递了什么信息？"答不出就删。

编号的正确用法：真实序列（步骤、阶段、榜单）；错误用法：并列的卖点、特性列表。

## 九、动效的 AI 默认病（Anthropic + emilkowalski）

- 每个区块都 fade-up 入场 → 改成**一个编排好的入场序列**，其余靠交互驱动
- 每张卡片都有 hover 抬升 → 只给可点击卡片
- 入场用 `ease-in`（错误）、退场比入场慢（错误）→ 入场 `ease-out`，出场 ≈75% 时长
- 无信息量的循环漂浮/呼吸 → 一屏 ≤2 个，只给"活的"元素（AI/实时/紧急）
