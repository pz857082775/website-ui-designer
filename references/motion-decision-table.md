# 动效决策表（Motion Decision Table）

> 动效只有一个用途：**降低理解成本**。说不出它服务哪一类，就删。
> 库选型与弹簧参数见 `motion-spec.md`；本文件只管"什么时候该有、该多久、怎么降级"。

---

## 一、五类动效（唯一分类法）

| 类别 | 时长 | 缓动 | 触发 | 目的 | 典型 |
|---|---|---|---|---|---|
| **状态反馈** | 100ms（80-120） | ease-out | 用户操作后立即 | 确认"收到了" | 按下缩放 .97、开关滑动、勾选 |
| **空间过渡** | 150ms（140-180） | ease-out | 元素出现/消失/移动 | 说明"从哪来、到哪去" | 展开收起、卡片位移、抽屉 |
| **导航理解** | 200ms（180-240） | ease-in-out | 层级或页面变化 | 说明"我在哪一层" | 页面转场、Tab 切换、面包屑 |
| **焦点引导** | ≤300ms | ease-out | 需要指向注意力 | 指向"下一步看这里" | 高亮、聚光、引导线、聚焦放大 |
| **等待安抚** | 循环 1.5-2s | linear（唯一允许） | 请求发出到返回 | 降低不确定焦虑 | spinner、骨架屏、进度条 |

**硬约束**
- 重复交互（同一动作反复发生）**≤500ms**
- 一屏同时动画 ≤3 个元素
- 焦点引导一屏只能有 1 个（与"一屏一个焦点"同源）
- 只动 `transform / opacity / filter / clip-path`；禁止动 `width/height/top/left/margin`

## 二、什么时候不该有动效

| 情况 | 判断 | 处理 |
|---|---|---|
| 高频操作（每分钟 >10 次） | 动效会变成噪音 | 只保留 ≤100ms 的状态反馈 |
| 键盘快捷操作 | 用户追求速度 | 无过渡，即时生效 |
| 首屏关键内容 | 动画延迟看到内容 | 不做入场，或 ≤150ms 且不影响 LCP |
| 表单校验 | 抖动会被误读为错误 | 用颜色 + 文案，不用 shake（除提交失败） |
| 数据刷新 | 会打断阅读 | 局部淡入（opacity 150ms），不整块重排 |
| 用户开启 reduced-motion | 可达性要求 | 全部归零，保留静态反馈 |

## 三、编排（Choreography）

**一个序列，不是一个集合。**
```
主元素先动（0ms）→ 次级（+60ms）→ 辅助（+120ms）
```
- 子元素交错 40-80ms（<40 看不出层次，>100 显得排队）
- 同屏只允许 1 个编排序列；其他元素静止
- 退场 = 入场 × 0.75（离开要更快）

**反例**：每个区块都 fade-up（这是 AI 生成页的典型指纹，因为省事）。

## 四、降级策略（必须实现，不是可选）

| 动效 | reduced-motion 降级 |
|---|---|
| 状态反馈 | 保留颜色变化，去掉缩放 |
| 空间过渡 | 直接显示/隐藏（无过渡） |
| 导航理解 | 交叉淡入（150ms）或直接切换 |
| 焦点引导 | 保留描边/高亮，去掉缩放 |
| 等待安抚 | 静态骨架 + 文案"加载中" |
| 记忆点（签名动效） | 直接呈现终态（不播放） |

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
    scroll-behavior: auto !important;
  }
}
```

## 五、功能模块 ↔ 动效映射表（交付必填）

```markdown
| 功能模块 | 动效 | 触发时机 | 目的（五类） | 时长 | 降级 |
|---|---|---|---|---|---|
| 提交工单 | 按钮勾线 + 转成功色 | 点击 | 状态反馈 | 120ms + 220ms 勾线 | 静态勾 + 文案 |
| 展开详情 | 高度 0fr→1fr + 8px 上移 | 点击卡片 | 空间过渡 | 150ms | 直接展开 |
| Tab 切换 | 内容淡入 + 指示条滑动 | 点击 Tab | 导航理解 | 200ms | 直接切换 |
| 模块聚焦 | 1.03 放大，其他 0.98/60% | 查看模块 | 焦点引导 | 280ms | 仅描边 |
| 列表加载 | 骨架屏 shimmer | 进入视口 | 等待安抚 | 1.5s 循环 | 静态骨架 |
```

**验收**：每一行都必须能说出"目的"，否则删掉该行。

## 六、性能红线

```
[ ] 只动 transform/opacity/filter/clip-path（零 Layout 块）
[ ] 中端设备 60fps（DevTools CPU 4x 降速）
[ ] 同时动画元素 ≤3
[ ] will-change 仅动画期间，结束移除
[ ] 首屏动画不阻塞 LCP（不延迟首屏文本可见）
[ ] 弹层/长列表用 transform 而非 height 动画
```

## 七、记忆点动效（唯一允许的"装饰"）

条件（全部满足才允许）：
1. 只有一个，且与品牌有关（专属缓动曲线 / 标志性转场 / 图形语言）
2. 只出现一次（最多重复 3 次）
3. 不阻断主任务，可跳过
4. 有 reduced-motion 终态
5. 时长 ≤400ms

示例：筛选条件变化时，结果数量滚动变化 220ms，同时下划线扫过一次——它同时承担"状态反馈 + 品牌记忆"。
反例：每张卡片 hover 都有粒子爆炸（装饰、重复、抢焦点）。

## 八、帧级纪律（整合自 frame-smith）

> 界面不是视频，但"把时间写成秒、把拍点写死"的方法直接可用。

### 8.1 时间用秒写，帧数由代码算
```
const FPS = 30;
const f = (s) => Math.round(s * FPS);
const H0 = f(0), H1 = f(0.2), H2 = f(0.45), H3 = f(0.8);
```
不要手猜帧号（"大概 12 帧"），那是抖动与不同步的主要来源。

### 8.2 任何时间映射都要 clamp
```js
const clampOpts = { extrapolateLeft: "clamp", extrapolateRight: "clamp" };
```
未夹取的斜坡会越过自己的拍点继续运动——这是"元素飘过头 / 回不到位"的头号原因。

### 8.3 拍点表（页面入场就是一条拍点线）

| 拍 | 时间 | 职责（一拍一件事） |
|---|---|---|
| H0 | 0ms | 第一眼：主视觉/主张出现（首屏 1.5s 内必须"成立"） |
| H1 | 120ms | 建立：次级信息就位 |
| H2 | 240ms | 展开：可交互元素可用 |
| H3 | 400ms | 落定：全部静止（此后不再有入场动画） |

**规则**
- 一拍只做一件事：既引入内容、又翻主题、又跑数字 = 三拍压成一拍，眼睛解析不了
- 第一拍要为第二拍"赚时间"：首屏 1.5s 内没有信息成立，用户就走了
- 最后一拍要**落定成设计过的终态**（不是"动画停了"）
- 无死气：每一拍不是运动就是有意停留

### 8.4 终态帧（Terminal frame）
每个动效都要能回答："如果它被冻结在任意一帧，这一帧是否仍然可读、可交付？"
- 导出/截图用的是终态帧，所以终态必须是设计过的构图，不是动画结束的残值
- `prefers-reduced-motion` 直接显示终态帧

### 8.5 尺寸系统（对应多端换算）
```
const S = width / 720;   // 竖屏基准 720 逻辑宽
fontSize * S; padding * S; borderRadius * S;
```
所有绝对像素都乘 S。这等价于小程序的 rpx 思路：**只写相对基准的比例，不写死像素**。

### 8.6 反廉价动效（视频与界面通用）
| 廉价指纹 | 为什么廉价 | 改成 |
|---|---|---|
| 所有元素用同一种方式入场（fade + translateY，同一个 ease，同时发生） | 这是模型最省事的默认 | 差异化：主元素先动、子元素 40-80ms 交错 |
| 可见位移上用 `linear` | 机械、没有重量 | ease-out 族 |
| 时长统一 0.5s | 没有节奏，像 PPT | 按四档分配 |
| 动画中途截断 / 卡顿 | 半成品引擎比没有更廉价 | 做不到就降级为静态 |
| 用"特效"代替"信息" | 说不出服务哪类功能 | 删 |
