# UI 能力持续迭代方法（可复用闭环）

> 结论先说：**刷图不会提升审美，拆参数才会。**
> 每次看参考，产出物必须是"能写进提示词的一条参数"，否则这次浏览等于零。

---

## 一、六步闭环（每次学习的最小单位）

```
① 收集 → ② 拆解 → ③ 参数化 → ④ 生成 → ⑤ 校验 → ⑥ 沉淀
                                    ↑                    │
                                    └──── 修正后再生成 ────┘
```

### ① 收集（3 分钟）
- 一次只带**一个目的**去资源库（看定价区 / 看空状态 / 看字体搭档）
- 收藏时必须写一句 **why**：`因为它用 X 手法解决了 Y 问题`
- 只收"真实产品"优先（Mobbin / SaaSUI / Stripe / Linear），概念图最后看

### ② 拆解（5 分钟，用八要素表）
对每一张收藏，按八要素快速过一遍，只填"有信息量的 3-4 项"：

```
布局：{App Shell / 分栏比例 / 内容最大宽}
模块：{它把信息切成哪几块，每块的组件类型}
排版：{标题/正文/元信息 的字号比例，字重对比}
配色：{背景/表面/文字/强调，强调色出现几次}
图标：{线性还是面性，软底还是裸放}
图像：{有没有主视觉，在左还是右}
动效：{入场是怎么编排的，有没有呼吸元素}
节奏：{区块间距，信息密度}
```

### ③ 参数化（10 分钟，本闭环最关键）
把观察翻译成**可执行参数**，写进三库之一（见第二节）：
- 值 → `--radius-card: 16px`、`font-size: 28px/750`
- 手法 → "标题跨出容器 20% 制造张力"
- 约束 → "一屏强调色不超过 5 处"

**检验标准**：这条参数写进提示词后，AI 能照着做出同样的效果。做不到 = 还没拆到底。

### ④ 生成（15 分钟）
用参数写提示词，生成一版。**同一个需求，同时跑两版**：
- A 版：你的新参数
- B 版：旧参数（基线）
两版必须只差一个变量，否则学不到因果。

### ⑤ 校验（5 分钟）
- `scripts/preflight.py`（0 ERROR）
- `review-rubric.md` 10 项验收条
- 最坏数据（超长姓名 / 六位数金额 / 0 条列表）
- 并排比对 A/B：哪一项变好了，哪一项变差了

### ⑥ 沉淀（3 分钟）
- 有效的参数 → 进"参数片段库"，并标注适用场景
- 无效的 → 进"反例库"，写清为什么不成立
- 同一手法验证 3 次都有效 → 升级为**默认值**，写进 `design-system-spec.md`

## 二、三库建设（你的资产，比收藏夹值钱）

### 库 1 · 风格卡（每张卡 = 一个可复用视觉方向）
```markdown
## {风格名}（来源：{站点}，{日期}）
气质：{三个词}
适用：{产品类型}
令牌：bg {#} / surface {#} / ink {#} / accent {#} / radius {px} / shadow {值}
排版：Display {px}/{weight} · Body {px}/{weight} · 字距 {值}
手法：{1-2 条关键手法，如"超大背景字 16% 透明度压在区块后"}
提示词片段：{五行式风格段}
反例：{这个风格做错会变成什么样}
```

### 库 2 · 参数片段库（按场景索引，直接粘进提示词）
```markdown
### 数据表格（来源：Stripe）
- 列对齐：文本左对齐、数字右对齐、等宽数字
- 行高 52px，分隔线 #EEF0F4，无斑马纹
- 行内 sparkline 60×20，末点实心
- 图表只做摘要，表格是真相
```

### 库 3 · 反例库（AI 味清单，越用越准）
```markdown
### {反例名}
长这样：{描述或截图路径}
为什么错：{违反了什么原则}
改成：{具体替换方案}
```

## 三、节奏（不需要每天两小时）

| 周期 | 动作 | 产出 |
|---|---|---|
| **每次做项目** | 跑完六步闭环 | 1-2 条新参数 |
| **每周 1 次 × 30 分钟** | 挑 3 张参考做拆解（不做生成） | 3 张风格卡 / 参数片段 |
| **每月 1 次 × 1 小时** | A/B 实验：挑 1 个不确定的参数，两版对比打分 | 1 条默认值升级或 1 条反例 |
| **每季 1 次 × 2 小时** | 体检自己的库：删过时、合并重复、更新旋钮默认值 | 更精简的规范 |

**关键不是频率，是"每次都留下东西"。** 一周一张卡，一年 50 张卡，你的提示词水平就是这 50 张卡的复利。

## 四、提示词迭代的四步法（针对你写提示词的专项训练）

### 第 1 步 · 建立基线
固定一个需求（比如"一个 SaaS 落地页"），用当前提示词生成，按评分卡打分 → 得到基线分。

### 第 2 步 · 单变量改动
一次只改一处：
- 只改字号跨度（3 倍 → 4.5 倍）
- 只改强调色预算（10 处 → 4 处）
- 只改动效强度旋钮（6 → 3）

### 第 3 步 · 盲评对照
两版截图并排，不看提示词，只问三个问题：
1. 哪一版更"像人做的"？
2. 哪一版 3 秒能看懂？
3. 哪一版删掉一个元素也不影响理解？

### 第 4 步 · 记录结论
```markdown
| 日期 | 变量 | A | B | 结论 | 是否升级为默认 |
|---|---|---|---|---|---|
| 10-22 | 字号跨度 | 3x | 4.5x | 4.5x 明显更有层级，但中文标题 >72px 易挤 | 部分采纳（中文上限 64px） |
```

## 五、三种"拆不动"的破解

| 卡住的表现 | 真正的原因 | 破解 |
|---|---|---|
| 只能说"好看"，说不出为什么 | 没有词汇 | 用八要素表强制逐项描述（哪怕描述得笨） |
| 拆出来了但写不进提示词 | 还是形容词 | 逼自己写成"数值 + 动作"，写不出就再看一遍 |
| 提示词改了但效果没变 | 变量太多 / 模型没能力 | 单变量 + 换更强的模型 + 把约束写成硬性禁止项 |

## 六、30 天起步计划（照做即可）

| 周 | 任务 | 验收 |
|---|---|---|
| W1 | 每天收藏 1 个真实产品界面，写 why；周末挑 3 个做八要素拆解 | 3 张风格卡 |
| W2 | 用风格卡重写自己过去写得最差的一个提示词 | 新旧两版生成图并排，评分提高 ≥5 分 |
| W3 | 做 1 次 A/B：只改"强调色预算"这一个变量 | 得出 1 条可复用结论 |
| W4 | 搭起三库骨架（风格卡 / 参数片段 / 反例），各填 ≥3 条 | 库能直接粘进下次提示词 |

---

## 七、一条最重要的原则

> **每次看到让你"哇"的界面，问自己一句：如果只能抄一个参数，抄哪个？**
>
> 抄对的参数，比抄整个页面有用一百倍。
