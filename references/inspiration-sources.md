# UI 灵感资源库（按"要解决什么"分类）

> 核实时间：2026-10。标注了两个重要变更：**Godly 已更名 `recent.design`**、**Design Vault 已并入 `screensdesign.dev`**。
> 使用原则：**不要刷图，要拆参数**。每个资源后面的"可借鉴要点"就是能直接写进提示词的东西。

---

## 一、找视觉方向（整站/整页）

| 资源 | 适用场景 | 可借鉴要点 | 费用 |
|---|---|---|---|
| **Awwwards** `awwwards.com` | 看年度最佳、判断"天花板在哪" | Hero 的单一编排、滚动叙事的节制、字体当作视觉主体 | 免费（Pro 付费） |
| **Recent**（原 Godly）`recent.design` | 动效与克制的当代审美 | 编辑式栅格、字号跨度、留白节奏；比 Awwwards 更少"炫技" | 免费 |
| **SiteInspire** `siteinspire.com` | 按风格/类型/主题筛选，做竞品调研 | 同一行业里各家怎么处理导航与首屏 | 免费 |
| **Httpster** `httpster.net` | 极简、强排版的方向 | 无装饰排版、单一强调色、大片留白 | 免费 |
| **Minimal Gallery** `minimal.gallery` | 找"极简但不空洞"的证据 | 用字体对比与色彩场替代装饰 | 免费 |
| **Curated.design** `curated.design` | 收集型灵感，按主题聚合 | 同一主题下不同解法并列对比 | 免费 |

**怎么用**：只取"构图与排版逻辑"，不取配色（配色看第五节）。

## 三、真实产品界面（后台 / B 端 / APP）★ 本技能最需要

| **Refero** `refero.design` | 11 万+ 带标签的界面，按模式筛选 | 定价表/onboarding/仪表盘按"模式"对比 | 免费 + Pro |
| **SaaSUI** `saasui.design` | 真实 SaaS 界面，按屏幕类型分类 + 每例有简短点评 | 信息密度、导航结构、数据可视化的取舍理由 | 免费 |
| **Page Flows** `pageflows.com` | 真实流程的**录屏** | 过渡时长、状态切换顺序（静图看不到的时序） | 付费（有试用） |

**B 端标杆产品（直接去看它们的产品截图）——2026 年最值得抄的 10 个**：

| 产品 | 抄什么 |
|---|---|
| **Linear** | 暗色优先的克制：近单色表面、一个强调色、密度高但不挤 |
| **Stripe** | 表格即界面：列对齐、行内 sparkline、右对齐等宽数字、图表只做摘要 |
| **Vercel** | 黑白系统：层级完全靠间距与字重；颜色只表达状态 |
| **Attio** | AI 原生界面：AI 摘要作为一等公民组件，而不是飘一个聊天气泡 |
| **PostHog** | 密集但亲和：每张洞察卡只回答一个问题 |
| **Hex** | 笔记本式仪表盘：分析过程本身成为界面 |
| **Retool** | 内部工具语法：组件栅格、表单与表格的实用排布 |
| **Mercury** | 金融的编辑式质感：让数字显得可信 |
| **Plausible** | 单页仪表盘：一屏讲完，图表极简 |
| **Supabase** | 复杂控制台的分区导航：一个模板装多种工具 |

## 十一、"要什么 → 去哪看"速查

| 你要的 | 第一个打开 |
|---|---|
| 定整站视觉方向 | Recent → Awwwards → SiteInspire |
| 抄某个区块（定价/特性/页脚） | Land-book（按区块筛选） |
| 做后台/仪表盘 | SaaSUI → Mobbin → Stripe/Linear 截图 |
| 做 App / 小程序 | Mobbin → ScreensDesign → Apple HIG / Vant |
| 定字体与字号阶梯 | Typewolf → Typescale → Practical Typography |
| 定配色 | Realtime Colors（放真实布局里试）→ Happy Hues |
| 加动效但不想俗 | Hoverstat.es → animations.dev → GSAP Showcase |
| 抄工程规范 | Ant Design / TDesign / shadcn 的令牌层 |
| 中文语境参考 | 站酷 → UI 中国 → 优设 |
| 训练判断力 | Brand New → Behance 案例 |

## 十二、使用纪律

1. **一次只带一个目的去**：这趟是看"定价区怎么排"，就别顺便看配色
2. **收藏必写一句 why**：没有 why 的收藏等于没收藏
3. **抄结构不抄皮肤**：布局逻辑可以学，配色字体必须换成自己的令牌
4. **优先真实产品**（Mobbin/SaaSUI/Stripe），少看 Dribbble 概念图——概念图不解决空状态、加载态、超长文本
5. **警惕趋势同质化**：所有画廊都在推同一种风格时，那正是它要变成新"AI 脸"的时候
