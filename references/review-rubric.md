# 交付验收与评审评分卡

来自 `educlopez/ui-craft`（10 项验收条 + 可评分批评）与 `Owl-Listener/designer-skills`（visual-critique 优先级清单）。
本文件是**交付闸门**：没过验收条不算完成；评分卡用于审已有界面（模式 B/C）。

---

## 一、10 项验收条（每页必过）

```
[ ] 1  层级：3 秒能看出主信息是什么
[ ] 2  令牌：颜色/字号/圆角/间距全部出自令牌，无 magic number
[ ] 3  配色：90% 中性 + 1 强调色；强调色每屏 3-5 次（Hick 定律），不超 5 次
[ ] 4  圆角：分级（输入 6 / 卡片 10 / 弹层 14 / 大容器 20），不是全站一个值
[ ] 5  阴影：环境光 + 直射光双层；不是单层黑影，也不是全靠 1px 描边
[ ] 6  字体：1 个正文族（可选 1 个展示族）；>24px 标题字距 ≤-0.02em；正文行宽 <80 字符
[ ] 7  动效：出场 ≈75% 入场时长；强度符合 MOTION_INTENSITY 旋钮
[ ] 8  状态：hover / focus-visible / active / disabled / empty / error 六态齐全
[ ] 9  无障碍：正文对比 ≥4.5:1、键盘可达、reduced-motion 降级
[ ] 10 独特性：有一个签名细节；删掉任一纯装饰不影响理解
```

**最终问题**（ui-craft 的原话门槛）：
> "Would a designer retouch this?" / "Would someone believe AI made this?"
> 任一答案为"是"，返工。

## 二、评分卡（评审已有界面时用）

### 2.1 三个轴

| 轴 | 评什么 | 权重 |
|---|---|---|
| **Distinction（独特性）** | 是否像"任何同类页面都会长这样" | 40% |
| **Craft（工艺）** | 排版/间距/对齐/细节精度 | 30% |
| **Usability（可用性）** | 可读、可点、可理解、可恢复 | 30% |

### 2.2 十项启发式（Nielsen）× 六条设计法则

| 启发式 | 检查点 |
|---|---|
| 系统状态可见 | 加载/处理中/成功有反馈吗 |
| 贴近真实世界 | 用用户语言还是系统语言 |
| 用户控制与自由 | 能撤销/返回/关闭吗 |
| 一致性与标准 | 同一动作是否同名同形 |
| 预防错误 | 危险操作有确认/约束吗 |
| 识别优于回忆 | 选项可见，不用记 |
| 灵活高效 | 熟手有快捷路径吗 |
| 美学与极简 | 每个元素都在服务任务吗 |
| 错误恢复 | 报错说清原因与修法吗 |
| 帮助与文档 | 关键处有提示吗 |

设计法则（量化检查）：
- **Fitts**：主要动作够大够近（≥44px，触屏）
- **Hick**：同屏选择 ≤5 个主选项，强调色 ≤5 处
- **Doherty**：交互反馈 <400ms
- **Miller**：分组 ≤7±2
- **Tesler**：复杂度要么在系统、要么在用户，别两边都扛
- **Cleveland-McGill**：图表编码按可辨识度排序——位置 > 长度 > 角度 > 面积 > 颜色

### 2.3 业务影响标签（给结论分级）
每个问题必须打一个标签，方便排优先级：

```
blocks-conversion  阻断转化（必须修）
adds-friction      增加摩擦（本周修）
reduces-trust      损害信任（本周修）
minor-polish       细节打磨（有余力再修）
```

### 2.4 评分公式
```
总分 = 0.4×Distinction + 0.3×Craft + 0.3×Usability
≥85 可交付 ｜ 70-84 需一轮打磨 ｜ <70 重做
任一项 ≤5/10 直接不通过（短板否决）
```

## 三、输出格式（评审结论必须长这样）

```
## 评审结论：{分数}/100 —— {可交付/需打磨/重做}

### 必须修（blocks-conversion / reduces-trust）
1. {问题} → {具体改法，含参数} → 影响：{标签}

### 建议修（adds-friction）
...

### 可选（minor-polish）
...

### 做得对的地方（保留）
1. ...
```

**纪律**：每条问题必须带"具体改法 + 参数"，禁止"建议优化间距"这种无法执行的结论。
