# 知识检索（RAG）——让提示词有据可依

核心问题：模型写 UI 提示词时容易"自由发挥"——凭印象给参数、凭感觉编规则。
本模块在生成前先检索库内依据，把"必须遵守 / 明确禁止"固定进提示词。

---

## 一、输入

| 输入 | 形式 | 说明 |
|---|---|---|
| **查询语句** | 自然语言，用户原话即可 | "后台首页 KPI 卡怎么排"、"页面太挤了"、"玻璃拟态导航怎么写" |
| **平台过滤**（可选） | `--platform pc/h5/miniapp/app` | 只返回该平台适用的条款 |
| **类型过滤**（可选） | `--type P/M/A/J`、`--kind card/ref` | 只要参数卡 / 只要反例 / 只要规范 |
| **返回条数** | `--top N`，默认 8 | 建议 4-6，太多会稀释重点 |
| **输出形态** | `--format table/prompt/json` | 人看 / 注入提示词 / 程序消费 |

命令：

```bash
python scripts/rag.py index                                  # 建索引（首次或内容变更后）
python scripts/rag.py query "后台首页 KPI 卡怎么排" --top 5
python scripts/rag.py query "页面太挤了" --platform h5
python scripts/rag.py query "入场动画" --type A --kind card    # 只看反例
python scripts/rag.py query "强调色" --format prompt           # 直接注入
```

---

## 二、检索范围

| 来源 | 内容 | 是否检索 |
|---|---|---|
| `references/*.md`（15 份） | 主规范、风格库、工作台规范、复刻/美化流程、平台矩阵、反 AI 脸、验收条等 | ✅ 按 `##`/`###` 切块（217 片段） |
| `ui-taste-engine/knowledge/` | 四类知识卡（P 参数 / M 手法 / A 反例 / J 判断），共 12 片段 | ✅ 整卡按章节切块，带置信度 |
| `tests/`、`evals/` | 实测页与回归用例 | ❌ 不检索（是产物，不是规则） |
| `README.md`、`CHANGELOG.md` | 使用说明与版本记录 | ❌ 不检索（会污染结果） |

知识卡目录默认自动寻找同级 `ui-taste-engine/knowledge`，也可用 `--kb <路径>` 指定。

**排序方式**（纯词法，零依赖，无向量库）：
1. BM25（k1=1.5，b=0.75）算基础分
2. 中文按二元组切词，英文按单词；口语同义词扩展（"挤"→间距/密度/留白/行高，"土"→饱和度/配色/色相）
3. 标题命中加权 ×(1+0.5×命中数)
4. 知识卡按置信度加权 ×(1+0.06×(置信-3))
5. 去重：同一张卡只留最高分片段；同一来源最多 2 条（保证结论多样）

## 三、输出表现

### 形态 1 · 表格（人看）

```
查询：后台首页 KPI 卡怎么排    命中 5 条（词元 8）

 1. [25.39] M-001·M            规则                          knowledge/patterns/M-001.md
 2. [15.26] dashboard-style.md 8.2 今日待办卡（首页 C 位）    references/dashboard-style.md
 3. [11.31] dashboard-style.md 二、KPI 卡解剖（第一组件）    references/dashboard-style.md
```

### 形态 2 · 注入块（喂给生成模型，**核心产物**）

```markdown
### 知识检索结果（针对：后台首页 KPI 卡怎么排）

**一、必须遵守（来自知识卡）**
- [M-001｜置信 4｜适用 所有后台首页的数据概览行] KPI 卡四段结构 —— 图标软底 40px →
  标签 13px 灰 → 数字 26-28px/750 tabular-nums → 趋势 12px

**二、明确禁止（来自反例库）**
- [A-001] CSS 预隐藏内容，CDN 失败时整页空白

**三、参考依据（规范片段）**
- references/dashboard-style.md › 二、KPI 卡解剖：…

**四、边界声明**
- 以上为知识库内的依据；未出现在此处的细节按通用规范处理，并标注来源或推断性质。
```

这个块整段粘到提示词第 3 段（设计令牌）之后、第 5 段（组件清单）之前。

### 形态 3 · JSON（程序消费）

```json
[{"score": 25.39, "kind": "card", "id": "M-001", "heading": "规则",
  "source": "knowledge/patterns/M-001.md", "confidence": 4}]
```

---

## 四、防"随意发挥"的三道闸

1. **分数阈值**：最高分 < `--min-score`（默认 1.0）时，注入块自动改写"边界声明"，
   要求模型标注"以下为推断"，**不得当作既定规范**
2. **无命中**：直接输出"无依据，按通用规范处理并标注推断"，不编造条款
3. **引用约束**：注入块每条都带 ID 与来源，评审时可回溯到具体文件

---

## 五、使用时机

```
需求 → ① 定旋钮 → ② RAG 检索（本模块）→ ③ 组装提示词 → ④ 生成 → ⑤ 验收
```

RAG 放在旋钮之后、组装之前：因为检索需要知道平台与页面类型才能过滤。

## 六、维护

| 什么时候重建索引 | 命令 |
|---|---|
| 修改/新增 `references/*.md` | `python scripts/rag.py index` |
| 新增知识卡（`kb.py add`） | 同上（索引不会自动更新） |
| 查询结果明显不对 | 先 `stats` 看片段数与词表，再重建 |

```bash
python scripts/rag.py stats
# 片段总数 / 规范数 / 知识卡数 / 词表大小 / 覆盖规范文件数
```

---

## 七、已知限制（不要过度期待）

- **纯词法检索**，没有向量语义匹配：同义表达靠内置同义词表，表外的说法可能召不回
- 英文查询效果弱于中文（文档以中文为主）
- 片段上限 900 字，超长表格可能被切断
- 它解决的是"**有依据**"，不解决"**依据对不对**"——依据质量由知识卡的置信度与验收体系保证
